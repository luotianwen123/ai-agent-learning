# 分块与重叠

分块（chunking）是把长文档切短的过程。切得好不好，直接决定检索能不能命中。

## 一、块为什么要短

两个原因。

第一，向量是有损压缩。一整篇三千字的文章压成一个向量，语义会被平均掉，任何具体问题都问不准。

第二，上下文有预算。一次能塞给模型的 token 有限，块太长，塞两三块就满了。

所以块的粒度，本质是"一个块能不能独立回答一个问题"。

## 二、定长切分与递归切分

**定长切分**最简单：每 N 个字切一刀。缺点是会把句子拦腰砍断。

**递归切分**按分隔符优先级逐层尝试：先找段落分隔（两个换行），找不到就找句号，再找不到就找换行，最后才硬切。

本项目用的是递归切分，分隔符优先级是：段落 → 句号 → 换行 → 竖线 → 分号 → 冒号 → 空格。

前面所有分隔符都找不到时，仍然要有一个兜底：按固定长度硬切。**这个兜底不能没有**，否则一整段没有任何标点的文本（比如代码）就永远切不动。

## 三、重叠（overlap）解决什么

如果只按固定长度硬切，一个完整的句子可能前半在你这一块、后半在下一块。检索时两边都只能召回半句。

重叠的做法是：每一块的开头，重复上一块结尾的 N 个字。

这样切点两侧的内容在两块里都完整存在，检索命中任意一块都能拿到完整上下文。

代价是存储和向量计算的量增加，所以重叠不能设得太大。

## 四、一个必须记住的坑

切分时"预留重叠空间"这一步很容易写错。

正确做法是：先算出每块的原始上限 = 块上限 − 重叠长度，按这个上限切，拼上重叠之后刚好等于块上限。

如果直接按块上限切、再在前面拼重叠，每块就会超长，超出的部分被截断，内容静默丢失。

## 五、重叠设为 0 会发生什么

在 Python 里，`prev[-0:]` 等价于 `prev[0:]`，取到的是**整个前一块**，而不是空串。

所以如果忘了判 `overlap > 0`，重叠为零时每一块都会把上一块全文重复一遍，文本整体膨胀，而且不报错。

这是一个典型的静默错：程序正常退出，结果全错。
