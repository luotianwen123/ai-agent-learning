# ai-agent-learning

三个从零手写的 AI Agent 项目，**主循环都不用框架**：一个可评测的 RAG 问答服务、一个手写 ReAct Agent、一个能自己改代码的 Coding Agent 内核。

写这三个是为了回答同一个问题：**一个大模型应用里，哪些部分是自己写的，哪些只是调 API。**

```
01  RAG 服务      ── 把检索做成工程件：四道分块校验 · 拒答阈值标定 · 4 指标评测 + 存档对比
02  ReAct Agent   ── 手写循环本身：Function Calling · 双出口终止 · 同工具 3 次熔断 · 跨进程状态
03  mini-pi       ── 造 Agent 内核：多轮闭环 · 工具层（读/写/跑） · 轨迹落盘 · case 回归集
```

| | 项目 | 一句话 | 可核对的证据 |
|---|---|---|---|
| **01** | [RAG 知识库问答服务](./01-rag-service/) | 把一个只读检索脚本做成可评测、可服务化、有拒答的问答服务 | `eval_runs/` 三份存档；10 道题的逐题排名；重排实验的负向结果 |

## 三个真踩过的难点

### 1. 分块边界 —— 12,661 字切 139 块，越界 0 次

长文档切块最容易出的问题是：切出来的块把一句话劈成两半，还悄悄丢了字符。
现在的做法是四道校验：**每块实际重叠量对账 → 边界越界检查 → 全文还原比对 → 坏块定位到行号**。

实测：语料 12,661 字 → 139 块，**边界越界 0/138**，**还原 12661/12661 字**。
还原比对是这几道里最有用的一个 —— 它不关心你怎么切，只问「拼回去是不是原文」。
少了它，前几道再绿也不能证明内容没丢。

### 2. 两段式重排的实测是负向的，所以默认关闭

做了双塔召回 + 交叉编码重排的对照实验，结果 **MRR 0.617 → 0.537**，变差了。

结论：**默认关闭，但保留开关**。原因是这个负向结果绑定在当前语料和 K 值上
（K_retrieve=10、K_report=5），换一份语料可能翻盘 —— 所以是「在这个配置下不成立」，
不是「重排没用」。这条记在 `01-rag-service/README.md` 的变更卡里，连同失败数据一起。

### 3. Agent 评测没有标准答案，只能断言确定性

RAG 有 gold（该命中哪个文件哪句话），Agent 没有 —— 同一个任务，模型每次走的路径都可能不同。
所以 mini-pi 的评测只断言**四类确定性信号**：

- 文件终态（存在性 + **字节级**内容比对）
- 工具调用序列（按序包含，**允许额外调用**）
- 终止原因
- **不该做的没做**（禁调工具列表）

实测暴露的第一个真问题：任务写的是「把 a.txt 内容**原样**写进 b.txt」，
模型读了 74 字节、写了 **73 字节** —— 末尾那个换行在转抄时丢了。
`exists` 断言判它 PASS，加字节比对后三次运行全部 FAIL（0/3）。
**没有字节断言时，这条用例每次跑都绿，而模型的行为从没被真正验证过。**

## 评测：数字，不是形容词

### RAG 检索（`01-rag-service/eval_runs/2026-11-04_093318.json`）

| 指标 | 值 |
|---|---|
| 语料 | 56 篇 / 3040 块 |
| **doc_recall@5** | **1.0** |
| **chunk_hit@5** | **1.0** |
| MRR | 0.617 |
| avg_rank_hit | 2.1 |

三次存档连起来看，语料增长时指标怎么变的是可解释的：

| 存档 | 篇 / 块 | MRR | avg_rank |
|---|---|---|---|
| 2026-11-02 15:28 | 55 / 2997 | 0.633 | 2.0 |
| 2026-11-02 15:40 | 56 / 3031 | 0.617 | 2.1 |
| 2026-11-04 09:33 | 56 / 3040 | 0.617 | 2.1 |

**这些 json 不是构建产物，所以进了版本库。** 同一配置换一份语料就是不同数字，
删了重建不出来 —— 证据链不能断在最后一步。

### Agent 侧（mini-pi）

| 项 | 现状 |
|---|---|
| 回归用例 | 1 条（`read_then_write`） |
| 跑法 | 同一条用例连跑 N 次，报 `c/n` 与 pass^k |
| 当前结果 | **0/3**（三次都卡在 73 vs 74 字节） |
| 工具输出指纹基线 | `0a8c1b0d5dfb`（`md5(read_file("a.txt"))[:12]`） |

## 已知限制

诚实列出来，因为下面每一条我都知道它卡在哪：

- **RAG 评测只有 10 道题。** 样本量太小，MRR 0.617 的置信区间很宽 ——
  它适合做「改了之后有没有变差」的对比，不适合当绝对水平。
- **mini-pi 只有 1 条回归用例。** 一条用例证明不了内核稳定，
  而且它现在是 0/3 稳定失败（模型做不到字节级原样复制）。
- **没有 CI。** 所有验证都是本地手动跑，`pytest` 还没接。
- **没有部署。** 01 有 FastAPI 壳但没上线，别人 clone 下来只能本地跑。

---

## 还要做什么

1. **给 mini-pi 补用例，把 pass^k 跑起来。** 现在只有 1 条，`RUNS=3`，
   套件级的 pass^k 没有意义 —— 至少要 5-10 条不同形态的用例（只读、改写、多文件、错误恢复）。
2. **接 pytest + GitHub Actions。** 现在每次验证靠手敲命令，
   同样的检查跑在 CI 上才算「改了能证明没改坏」。
3. **11 有 FastAPI 壳，把它部署上去。** 一个能点开的链接比十段说明有用。
